KAILU CREATION — Excel Catalog Sync Fix
=======================================

જૂના buildનું કારણ અને વર્તમાન V2 સ્થિતિ
----------------------------------------
જૂના buildમાં Excel Sync source/deployment વચ્ચે mismatch હતો. વર્તમાન V2 packageમાં `index.html` પહેલાં bundled `products-data.js` snapshot, પછી `script.js` દ્વારા initial render, અને ત્યારબાદ `catalog-sync.js` દ્વારા Excel fetch/sync load કરે છે. આ ક્રમ initial catalog render જાળવે છે અને Excel sync ને અલગથી ચલાવે છે. `kailucreation.in` V1 domain છે; આ ZIP V2 preview માટે છે.

આ પેકેજમાં શું છે
-----------------
1. catalog-sync.js — Websiteના જ rootમાં રહેલી `Kailu Creation Catalog List.xlsx` નો fetch અને 20-column validation.
2. index.html — અલગ cache versions સાથે `products-data.js`, `script.js`, `catalog-sync.js`, Firebase config અને customer-account module load કરે છે. Catalog script શરૂઆતનું product render અટકાવતું નથી; તે Excel sync backgroundમાં શરૂ કરે છે.
3. script.js — Excel Sync સફળ હોય ત્યારે `Synced from Excel`; નિષ્ફળ જાય તો `Sync Failed — Showing Last Synced Data` અથવા `Sync Failed — Showing Backup Data` દેખાડે છે.
4. `.nojekyll` — GitHub Pages પર static files માટે.
5. આ V2 preview packageમાં `CNAME` નથી, જેથી V1ના `kailucreation.in` domainમાં અનિચ્છિત ફેરફાર ન થાય.

V2 Preview Website અપડેટ કરવાના પગલાં
-------------------------------------
1. GitHubમાં `Kaklotar9985/KAILU-CREATION-V2` repository ખોલો.
2. આ ZIPમાંથી `KAILU-CREATION-V2-main` folderની website files repositoryના rootમાં upload/replace કરો; તેમને વધારાના subfolderની અંદર ન મૂકો.
3. V2 repositoryમાં `CNAME` હોય અને તે `kailucreation.in` બતાવતું હોય તો તેને V2 repoમાંથી દૂર કરો/તે custom domain set ન કરો. V1ની `KAILU-CREATION` repositoryમાં રહેલું `CNAME` **બદલશો કે delete કરશો નહીં**.
4. GitHubમાં commit કરો અને `https://kaklotar9985.github.io/KAILU-CREATION-V2/` ખોલીને preview ચકાસો.
5. Product Summaryમાં `Synced from Excel` દેખાવું જોઈએ. નવી Excel publish કરવા એ જ V2 repositoryના rootમાં `Kailu Creation Catalog List.xlsx` ને replace અને commit કરો.
6. V1ના `kailucreation.in` પર deploy ફક્ત અલગથી ઇરાદાપૂર્વક production migration નક્કી કર્યા પછી જ કરવું.

મહત્વપૂર્ણ
----------
- Computerમાં local Excel save કરવાથી GitHub Pages પરની ફાઇલ આપમેળે બદલાતી નથી. Excelને GitHub/hosting પર Upload અને Commit કરવી પડે છે. આ package browser-side sync કરે છે; તે તમારી તરફથી GitHubમાં files upload/commit કરતું નથી. આ Customer Account update માટે V2 preview repositoryનો જ ઉપયોગ કરો; V1 live domainને અસ્પર્શિત રાખો.
- Excelની 20 headers names (spaces/punctuation સિવાય) અને `Kailu Creation Catalog List` sheet જાળવો.
- એક જ catalogના size variant rowsમાં Category, Product Name, Color, tag, Fabric, Description અને Image/Video Links consistent રાખો. Inconsistency/duplicate SKU થાય તો sync સ્પષ્ટ error સાથે reject થશે અને છેલ્લી સારી data snapshot જાળવાશે; તે જૂના dataને `Synced from Excel` તરીકે દર્શાવશે નહીં.
- Excel CDN/Fetch નિષ્ફળ જાય તો status warning દેખાશે; last-synced browser cache અથવા bundled backup data વપરાઈ શકે.
- Google Sheets order backend (`Code.gs` / Apps Script) આ package દ્વારા આપમેળે deploy થતું નથી. હાલની deploy થયેલી Apps Script URL જ વપરાય છે.

PC LOCAL TEST — FILE:// MODE FIX
================================
જો Chrome address barમાં `C:/.../index.html` અથવા `file:///.../index.html` દેખાય, તો Excel Sync `fetch()`થી નહીં ચાલે. Updated package direct local file modeમાં Excel Picker બતાવે છે: `Ctrl + F5` કરો, પછી તાજેતરમાં Save કરેલી `Kailu Creation Catalog List.xlsx` પસંદ કરો. `Synced from Excel` જ સફળ પરિણામ છે. `Sync Failed — Showing Backup Data` આવે તો જૂનો data છે.

બીજો વિકલ્પ: `START-LOCAL-TEST.bat` ચલાવો. Browser address `http://127.0.0.1:8765/` હોવો જોઈએ. Excel આ જ folderમાં Save થયેલી હોવી જોઈએ. Save પછી Ctrl+F5 કરો.
